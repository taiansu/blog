# 譯序

前陣子有幾個人跟我提到 [Codeware](http://www.codewars.com/dashboard)。註冊了帳號玩了幾關，設計跟介面蠻不錯。但有一件事一直梗在我心裡，是這網站把每個練習叫做「Kata」，這個詞源想來是 從 [software craftsmanship](http://manifesto.softwarecraftsmanship.org) 及 Dave Thomas 去年的 [CodeKata](http://codekata.com) 來的。我做了幾題測驗，前面都是在試你對各個語言的功能的熟悉度。我不知道繼續做下去是不是真的能帶到所謂 CodeKata 等級的東西，也不太知道這個要怎麼測。我想先起個頭翻譯一下 Dave Thomas 原先的文章，再來看看怎麼發展。

空手道的 Kata 在中文的稱呼是"套路"或是"型"，因此 CodeKata 有人翻成[編程套路](https://www.google.com.tw/#q=編程套路&safe=off)，我不太喜歡因為聽起來有點 cliché 的感覺。"編程型"又好像在講 3D 印表機。想了一個"編程演武"，聽起來很帥但是似乎太強調表演、太公開了。所以 Kata 這個字就先留著不動吧。

# CodeKata
  要怎樣才能成為一個更好的樂手？學樂理會有點幫助，理解自己樂器的運作原理也一樣。有天份當然也幫得上一點忙。但是到最後，超凡的能力總是來自於練習。在練習中一次又一次用上你學到的理論，吸收過程中的經驗來持續進步。

要怎麼成為一個明星運動選手？顯然健身跟天賦也有點用。但是最棒的選手每天總是花上好幾把鐘頭，不斷不斷的練習。

但在軟體領域裡，開發者讀完理論之後，就直接被丟到戰場上，立刻與專案搏鬥。這好像領著一群小朋友，然後跟他們說我們要有四小節的時間去打敗芝加哥紅人隊 ( 嘿，我們有用上目標管理喔！)。 在軟體領域裡，我們直接用工作當練習，所以我們會在工作上犯錯。我們迫切需要找個把練習跟職場工作分開的方式。我們需要練習專用的時段。

## The Kata

怎樣才算是好的練習？首先你需要一段不會被打擾的時間，還有一個想試試看的小東西。你得儘可能的多嘗試幾次，並輕鬆看待犯錯這件事。但你得仔細觀察結果及尋求回應，這樣才知道該怎麼改進。必須完全沒有壓力，而這些正是在專案環境下很難練習的原因。練習會保持編程的樂趣: 當你有空的時候，試著前進一小步，而在旅程的最後，你會發現你比開始練習前多懂了許多。

Code Kata 是試著想把這種練習的元素帶進軟體開發的嘗試。Kata 是空手道中的一種練習方式，你一次又一次的重覆某個固定的招式，而每一次都進步一點點。code kata 背後的意圖就類似這樣。每一個練習都蠻短的 ( 大約 30 分鐘到一個小時 )。有些會需要寫 code，而且可以用很多不同的方法寫。有些沒有答案，而是需要思考一些編程背後的問題。這些都不太可能有單一的正確解答。我大約每週會加一個新的 kata。你可以花點時間來試試看。

要記得，Kata 的重點不在於找到正確的答案。而是在於在過程中所學到的事。目的是練習，而非解答。
