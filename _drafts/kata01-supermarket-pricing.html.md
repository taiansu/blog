這個編程套路是從某個 DFW Practioners meetings 的討論裡來的。問題的領域看起來似乎很簡單：「超市裡貨物的定價」。

超市裡某些東西的定價很簡單：這罐豆子要 0.65 美元。某些東西則有很複雜的價格，例如：

* 三個一美元 ( 如果我買四個或五個該怎麼算？)
* 一磅 1.99 美元 ( 那四盎斯要多少？) #註： 1 磅為 16 盎斯。
* 買兩個，送一個 ( 那第三個物品的金額是多少？ )

這個套路不需要寫程式。此練習是讓你嘗試想出多個足夠處理這些(以及更多)定價策略的金額 / 價格模型。而且這概念在很多地方都是通用的(例如：旅館櫃台、庫存管理、點餐櫃台等等)。花點時間想一想以下幾個問題：

* 分數的金額存在嗎？
* 捨去小數(如果有的話)發生在什麼時候？
* 你要怎麼保存定價策略的審計記錄(audit trail)？以及這個資料是必要的嗎？
* 成本 (cost) 跟價格 (price) 是同一個東西嗎？
* 如果一個放了 100 個罐頭的貨架，定價為買兩罐送一罐，這貨架上的東西值多少錢？

這是一個經典的暖身套路，但是要小心。某些問題比他表面上看起來的還要狡猾。我建議你可以花幾個星期去盡力思考出幾種可能的解法。

## 目標
這個編程套路的目的在於嘗試規劃較寬鬆的模型。盡可能多想幾個可以處理這些問題的解法。並思考它們各自的優缺點及取捨。在比較各種模型的時候你會用到什麼技術？在記錄模型的時候呢？你如何驗証這個模式可行？

---

## 什麼是編程套路 ( Code Kata )？

* 找個你不會被打擾的時間跟地點
* 專注在型的基本元素上
* 記得在幾個重要的決定後，徵尋他人的意見
* 如果有用的話，把你的進展記錄下來
* 找幾個

這些編程套路是沒有正確或是錯誤的答案的。讓你有所獲益的是過程，而非結果。
